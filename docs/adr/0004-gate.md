# ADR-0004: The gate — approved scenarios, behavior diff, mutation proof

- Status: accepted
- Date: 2026-11-13

## Context

AI-written PRs routinely ship with passing unit tests that encode the wrong
behaviour (the north-star demo: cancel _immediately_ instead of _at period end_,
with a green mocked unit test). Review of the diff is expensive; we want the
change judged by black-box checks a human approved _before_ the code existed,
and evidence that those checks have teeth.

## Decision

1. **Spec → scenarios → approval.** A ticket (`.sluice/gate/<ID>/ticket.yaml`)
   holds the spec. Scenarios (`scenarios/<id>.yaml`) are proposed by anyone —
   an agent over MCP (`sluice_gate_propose_scenarios`), a generator command
   (`sluice gate propose --command`: ticket YAML on stdin, scenario YAML out, so
   any LLM CLI can generate them), or by hand. A human approves with
   `sluice gate approve` or the web UI; the approval is bound to the sha256 of
   the scenario's canonical content, so any edit makes it _stale_.
   **Approval is not exposed over MCP**: agents cannot approve their own checks.
2. **Definitions come from base.** `sluice gate run` reads ticket, scenarios,
   approvals and `sluice.yaml` from the base revision; a PR that touches
   `.sluice/gate/**` fails. The sandbox image is built from head (so new deps
   work) but its spec comes from base.
3. **Black-box checks.** A scenario is a script (http/advance/clock) with
   `expect` on responses and `assert` steps over fake state (`fake`), the DB
   (`sql`), outbound calls (`egress`) and domain events (`events`). Matching is
   partial with operators (`$len`, `$contains`, `$regex`, `$gt`, …) and treats
   equal instants as equal across ISO spellings. Each scenario starts from a
   pristine sandbox.
4. **Behavior diff vs base.** Every approved scenario also runs on base; the
   evidence diff (ADR-0003) shows what the PR changed in API responses, egress,
   DB writes, events and final state.
5. **Mutation proof.** Mutants are generated with the TypeScript compiler API
   (parses JS and TS) **only on lines the PR changed** inside mounted source
   dirs: operator swaps, boolean/number/string literals, removed negations,
   negated conditions, removed calls, dropped return values. A mutant is
   _caught_ if any scenario's outcome differs from the unmutated head (so it
   works for failing PRs too). Default 10 mutants, evenly spread; if all
   scenarios pass but fewer than `threshold` (default 80%) are caught, the gate
   fails: "checks too weak".
6. **Outputs.** JSON + self-contained HTML report (`.sluice/reports/`), terminal
   text, and a GitHub check run (Markdown summary + per-scenario diffs +
   mutation table). Surfaces: CLI (`--github-check`), GitHub Action
   (`surfaces/github/action`), the "Sluice Gate" GitHub App
   (`surfaces/github`, webhook → App JWT → installation token → clone → gate →
   check run), MCP tools, and the local web UI.
7. Optionally the PR's own unit tests run inside the app image with
   `--network none`; shown for contrast only.

## Dependencies

| Dependency                              | Where                          | Why                                                                                                                         |
| --------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| typescript (runtime)                    | plugin-gate (and leases later) | one parser for JS + TS mutants and symbol indexing; boring, ubiquitous                                                      |
| @modelcontextprotocol/sdk               | surfaces/mcp                   | reference MCP implementation                                                                                                |
| `@sluice-dev/github-api` (new core pkg) | gate, github surfaces, policy  | tiny fetch-based client; avoids Octokit's surface for ~10 endpoints and lets every consumer point at the fake or the broker |
| GitHub REST OpenAPI subset              | fakes                          | GitHub fake is contract-validated like Stripe                                                                               |

## Consequences

- Gate cost ≈ (scenarios × 2 + mutants × ≤scenarios) sandbox resets; ~25–40 s
  per PR for the demo on a laptop.
- Equivalent mutants can survive; the report lists every survivor so a human
  can add a scenario or accept the gap.
